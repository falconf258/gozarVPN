# GozarVpn

یک رابط گرافیکی مدرن، تمام‌امکانات و با تم نارنجی/مشکی برای هسته‌ی خط‌فرمانی **Aether** (نسخه ویندوز)، ساخته‌شده با Electron.

📋 برای دیدن دقیق هر چیزی که در هر نسخه تغییر کرده (باگ‌فیکس‌ها، قابلیت‌های جدید)، فایل [CHANGELOG.md](CHANGELOG.md) را ببینید — هر تغییری که از اینجا به بعد اعمال شود آنجا مستند می‌شود.

⚠️ **قبل از هر کاری این بخش را بخوانید — نام و برندینگ**
سورس اصلی Aether تحت مجوز **AGPL-3.0** است، اما یک فایل جداگانه `TRADEMARK.md` دارد که صراحتاً می‌گوید:
نام «Aether»، لوگو و برندینگ آن **متعلق به CluvexStudio است** و استفاده از آن در پروژه‌های مشتق (مثل همین GUI) **بدون اجازه‌ی کتبی مجاز نیست**، حتی اگر کد را طبق AGPL آزادانه استفاده/توزیع کنید.
یعنی:
- برای استفاده‌ی شخصی/داخلی همین الان مشکلی نیست.
- اگر می‌خواهید این GUI را **عمومی منتشر کنید** (گیت‌هاب عمومی، کانال تلگرام، سایت و…)، باید **نام و آیکون را عوض کنید** (این پروژه فقط برای نمونه «Aether» نام‌گذاری شده) یا از تیم CluvexStudio اجازه بگیرید. آیکون روباه/نارنجی-مشکیِ این پروژه هم صرفاً یک طرح جنریک الهام‌گرفته است، نه لوگوی رسمی — باز هم بهتر است قبل از انتشار عمومی عوضش کنید.
- نام و شناسه‌ی بسته را در `package.json` (`name`, `productName`, `appId`) و در `src/main/constants.js` به دلخواه تغییر دهید.

## این پروژه چیست؟

هسته‌ی اصلی Aether (نوشته‌شده به Rust) هیچ تغییری نمی‌کند — این پروژه فقط دور آن یک رابط گرافیکی می‌کِشد:

- `aether.exe` را با دقیقاً همان متغیرهای محیطی‌ای که خود CLI پشتیبانی می‌کند (`AETHER_PROTOCOL`, `AETHER_SCAN`, `AETHER_NOIZE`, …) اجرا می‌کند — این‌ها مستقیماً از `aether/src/cli.rs` استخراج شده‌اند، پس هر گزینه‌ای که نسخه‌ی ترمینال دارد این‌جا هم هست.
- خروجی لاگ را زنده در یک کنسول نمایش می‌دهد و وضعیت اتصال (اسکن/در حال اتصال/متصل/خطا) را از روی همان پیام‌های لاگ خود هسته تشخیص می‌دهد.
- پروفایل‌های متعدد تنظیمات را ذخیره می‌کند.
- آیکون Tray برای اتصال/قطع سریع دارد.
- **دو مسیر به‌روزرسانی جدا** دارد (پایین توضیح داده شده).
- هنگام اتصال، **پراکسی سیستم ویندوز را خودکار روی تونل تنظیم می‌کند** (و موقع قطع برمی‌گرداند) — بدون این کار، بالا آمدن پراکسی محلی به‌تنهایی هیچ ترافیکی را واقعاً از تونل رد نمی‌کند. از تب «تنظیمات برنامه» قابل غیرفعال‌سازی است.
- یک تب **«اسکنر IP»** دارد که با ابزار جانبی [CloudflareSpeedTest](https://github.com/XIU2/CloudflareSpeedTest) آی‌پی‌های Cloudflare را تست کرده و امکان اعمال یکی از آن‌ها به‌عنوان Peer اجباری (`AETHER_PEER`) را می‌دهد. **این تست فقط TCP:443 را می‌سنجد، نه پروتکل UDP واقعیِ Aether** — جزئیات و محدودیت‌ها داخل خودِ تب توضیح داده شده.

## پیش‌نیازها برای توسعه/build

- Node.js نسخه ۲۰ به بالا
- یک نسخه‌ی build‌شده‌ی `aether.exe` — یا با `cargo build --release` از سورس اصلی بسازید، یا از صفحه‌ی Releases مخزن اصلی (`CluvexStudio/Aether`) دانلود کنید.

## اجرا در حالت توسعه

```bash
npm install
npm start
```

هسته را به‌صورت دستی معرفی کنید: در تب «به‌روزرسانی» → «انتخاب دستی فایل exe» یک `aether.exe` را انتخاب کنید، یا آن را در پوشه‌ی `resources/core/aether.exe` کنار بگذارید تا هنگام build داخل برنامه باندل شود.

## ساخت نصب‌کننده‌ی ویندوز

روی ویندوز یا در CI (پایین را ببینید):

```bash
npm run dist
```

خروجی در `release/` قرار می‌گیرد: هم یک نصب‌کننده‌ی NSIS و هم یک نسخه‌ی Portable.

> ساخت روی لینوکس هم تا مرحله‌ی پکیج‌کردن (`win-unpacked`) کار می‌کند، اما ساخت فایل نصب‌کننده‌ی نهایی امضاشده روی لینوکس نیاز به `wine` دارد. ساده‌ترین راه، استفاده از همان workflow گیت‌هاب اکشنز پایین است که روی یک runner واقعی ویندوز build می‌گیرد.

## دو مسیر به‌روزرسانی — چیزی که خواسته بودید

### ۱) به‌روزرسانی «هسته» (`aether.exe`)

وقتی نسخه‌ی جدیدی از هسته در Releases مخزن `CluvexStudio/Aether` منتشر شود (asset با نام `aether-windows-x86_64.zip`)، از تب **«به‌روزرسانی»**:

1. «بررسی به‌روزرسانی هسته» → نسخه‌ی نصب‌شده را با آخرین Release مقایسه می‌کند (از GitHub API).
2. اگر جدیدتر بود، «به‌روزرسانی هسته» را بزنید: دانلود می‌شود، **چک‌سام SHA-256** را (اگر asset مربوطه موجود باشد) تأیید می‌کند، اتصال فعلی را (اگر برقرار بود) قطع می‌کند، فایل را جایگزین می‌کند و دوباره وصل می‌شود.

هیچ کامپایل یا کار دستی‌ای لازم نیست — دقیقاً همان چیزی که خواسته بودید.

اگر روزی هسته را از مخزن دیگری (فورک خودتان) توزیع کردید، فقط سه مقدار را در `src/main/constants.js` عوض کنید:
`CORE_REPO_OWNER`, `CORE_REPO_NAME`, `CORE_WINDOWS_ASSET`.

### ۲) به‌روزرسانی «خود برنامه» (GUI)

از پکیج `electron-updater` استفاده شده که مستقیماً به Releases گیت‌هاب همین پروژه‌ی GUI وصل می‌شود. یعنی وقتی شما (توسعه‌دهنده) نسخه‌ی جدید GUI را طبق مراحل زیر منتشر کنید، همه‌ی کاربران به‌صورت خودکار پیام «نسخه‌ی جدید موجود است» را می‌بینند و با یک کلیک دانلود/نصب می‌شود.

**راه‌اندازی یک‌باره:**

1. یک مخزن گیت‌هاب برای همین GUI بسازید (مثلاً `your-user/aether-gui`).
2. در `package.json` بخش `build.publish` و در `src/main/constants.js` مقادیر `GUI_REPO_OWNER`/`GUI_REPO_NAME` را با نام مخزن خودتان جایگزین کنید.
3. هر بار خواستید نسخه‌ی جدید منتشر کنید:
   - نسخه را در `package.json` بالا ببرید (مثلاً `1.0.1`).
   - `git tag v1.0.1 && git push --tags`
   - GitHub Actions (`.github/workflows/release.yml`) خودش روی یک runner ویندوزی build می‌گیرد و نصب‌کننده را در Releases منتشر می‌کند.
   - `electron-updater` این Release را خودکار پیدا می‌کند.

> نکته: امضای دیجیتال (code signing) برای نصب‌کننده تنظیم نشده. بدون آن، ویندوز SmartScreen هنگام اجرا هشدار «ناشر ناشناس» می‌دهد (کاربر با «More info → Run anyway» رد می‌شود، اما تجربه‌ی خوبی نیست). برای رفع کامل باید یک گواهی Code Signing (EV یا OV) از یک CA بخرید و در `package.json → build.win` تنظیمات `certificateFile`/`certificateSubjectName` یا امضای مبتنی بر Azure Trusted Signing را اضافه کنید.

## ساختار پروژه

```
src/main/        فرآیند اصلی Electron (اجرای هسته، به‌روزرسانی‌ها، ذخیره‌سازی، Tray)
src/preload/     پل امن contextBridge بین رندر و main
src/renderer/    رابط کاربری (HTML/CSS/JS ساده، بدون فریم‌ورک سنگین)
resources/       آیکون‌ها (و اختیاری: resources/core/aether.exe برای باندل کردن)
build/           آیکون نصب‌کننده (icon.ico)
.github/workflows/release.yml   build و publish خودکار روی تگ گیت
```

## نکات امنیتی که از سورس اصلی به ارث رسیده

- پراکسی SOCKS5 هیچ authenticationـی ندارد؛ فقط روی `127.0.0.1` گوش می‌دهد (پیش‌فرض `AETHER_SOCKS=127.0.0.1:1819`) — این را در تنظیمات تغییر ندهید مگر بدانید دارید چه‌کار می‌کنید.
- توکن‌ها و اطلاعات Zero Trust (Access Secret/Token) در `electron-store` به‌صورت متن ساده روی دیسک کاربر ذخیره می‌شوند. اگر لازم شد، می‌توان با گزینه‌ی `encryptionKey` در `electron-store` رمزگذاری اضافه کرد.
